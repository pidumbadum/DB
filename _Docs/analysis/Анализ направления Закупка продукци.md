# Анализ направления "Закупка продукции"

## Основные таблицы

### bm_StorageOperations

Центральная таблица направления, хранит факты всех операций движения товаров. Содержит 13,4 миллиона записей. Каждая строка представляет собой единичную операцию с указанием товара, количества, цены и суммы.

Ключевые поля для анализа закупок:
- **OperationID** — идентификатор типа операции (1 = Поступление, 2 = Списание)
- **ProductID** — ссылка на товар
- **VendorID** — ссылка на поставщика/контрагента
- **PriceCost** — закупочная цена (себестоимость)
- **Quantity** — количество в операции
- **Amount** — сумма операции
- **Period** и **DateAdd** — временные метки для периодического анализа

Для анализа закупок отбираются записи с `OperationID = 1` (Поступление).

### bm_StorageOperations_Table

Архивная таблица операций хранения. Имеет идентичную структуру основной таблице, но содержит исторические данные с непересекающимися идентификаторами. Используется для долгосрочного анализа без влияния на производительность основной таблицы.

## Справочные таблицы

### product

Справочник номенклатуры товаров. Содержит описания позиций (например, "Бананы"), идентификаторы поставщиков (`vendorid`), ценовые группы и базовые цены. Связывается с основной таблицей через поле `ProductID`.

### pricelist

Таблица прайс-листов. Хранит актуальные и исторические цены по товарам с привязкой к документам (`DocumentID`), поставщикам (`vendorid`) и базовой стоимости (`basecost`). Позволяет отслеживать динамику закупочных цен во времени.

### bm_JournalBarnetDocs

Таблица документов-оснований. Каждая операция в `bm_StorageOperations` ссылается на документ через `DocumentID`. Документ содержит информацию о контрагенте (`CompanyID`), типе документа (`DocumentTypeID`), дате оформления (`DateAdd`) и периоде (`Period`).

## Справочники типов

### bm_JournalType

Справочник типов журналов учёта (например, "Хозяйственный учет"). Определяет, к какому виду учёта относится документ.

### bm_JournalTypeDocuments

Справочник типов документов (например, "Ввод состава нового рецепта"). Классифицирует документы по их назначению в бизнес-процессах.

### bm_StorageOperationsType

Справочник типов операций хранения. Определяет направление движения товара и его влияние на остаток через поле `Factor` (1 — приход, -1 — расход).

## Связи между таблицами

```
bm_StorageOperations
    ├── ProductID → product (товар)
    ├── VendorID → product.vendorid (поставщик товара)
    ├── DocumentID → bm_JournalBarnetDocs (документ-основание)
    │       ├── CompanyID → bm_Companies (контрагент)
    │       ├── JournalID → bm_JournalType (тип журнала)
    │       └── DocumentTypeID → bm_JournalTypeDocuments (тип документа)
    └── OperationID → bm_StorageOperationsType (тип операции)

bm_StorageOperations_Table
    └── DocumentID → bm_JournalBarnetDocs (архивные операции)

pricelist
    └── DocumentID → bm_JournalBarnetDocs (цены в документах)
```

## Примечания по качеству данных

- Справочник `bm_Companies` содержит только одну запись — является заглушкой, реальные данные о поставщиках хранятся в поле `vendorid` таблицы `product`.
- Справочник `storages` содержит только одну запись — система работает с единым складом.
- Таблицы `bm_CashOperations`, `bm_PaymentOperations`, `bm_JournalBarnetDocs_Actions`, `bm_JournalBarnetDocs_Info`, `bm_ManufactureOrders`, `hotel_registr` не содержат данных и не участвуют в анализе.
